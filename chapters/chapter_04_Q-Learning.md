### 序：从 Bellman 两种方程，到 Q-Learning

这一章先不背公式，先抓一个更根本的问题：

> **如果未来会影响当前决策，那 Agent 到底该怎么把"未来"压缩进"现在"的动作选择里？**

这就是第三章 Bellman 两种方程真正解决的问题。

如果按第一性去推，路径其实很自然：

- **什么问题？** 眼前 reward 不够，动作的好坏取决于它会把我带到什么未来
- **如何推导解决方案？** 把长期回报拆成：`当前一步 reward + 折扣后的未来价值`
- **会分裂成哪两条路？**
  - 如果我要评估当前策略，就得到 `Bellman Expectation Equation`
  - 如果我要寻找最优动作，就得到 `Bellman Optimality Equation`
- **第四章为什么必须继续往前走？** 因为只有方程还不够，我还需要一个能靠采样数据真正把 `Q(s,a)` 学出来的算法

先把这一章的主线钉住：

> **Bellman 告诉我们正确答案该满足什么结构，Q-Learning 负责用经验数据一步步逼近这个结构。**

---

#### 1. 什么问题逼出了 Q-Learning？

第三章里我们已经知道：

- `Bellman Expectation Equation` 回答：**按当前 policy 继续走，平均会有多好？**
- `Bellman Optimality Equation` 回答：**如果后面每一步都选最优动作，最多能有多好？**

这两条方程已经把"长期价值"的结构讲清楚了。

但它们还没有解决一个工程上真正要命的问题：

> **我知道正确关系长什么样，可我怎么在不知道真值、也不知道完整环境模型的情况下，把它学出来？**

这就是第四章要接手的问题。

---

#### 2. 出发点：我需要的不是状态整体好不好，而是动作到底哪个好

如果我只有：

```math
V(s)
```

那我只知道：

- 这个状态整体上值多少钱

但真正做决策时，我需要的是：

- 往左好还是往右好？
- 现在踩油门值不值？
- 当前这个动作会不会把我带向更好的未来？

所以仅有状态价值还不够。

这会自然逼出一个更细的量：

```math
Q(s,a)
```

它表示：

> **在状态 `s` 下，如果我先做动作 `a`，未来总回报大概是多少？**

也就是说：

- `V(s)` 看的是"这个状态整体怎么样"
- `Q(s,a)` 看的是"在这个状态做这个动作怎么样"

而第四章真正想学会的，就是这个 `Q`。

---

#### 3. 如何从 Bellman 两种方程推到 Q-Learning？

如果我只是想评估当前策略，那我会沿着 `Expectation` 那条线继续走。

但如果我的目标是：

> **不只是评价当前打法，而是直接逼近最优动作价值。**

那就必须沿着 `Bellman Optimality Equation` 继续往下推：

```math
Q^*(s,a) = \mathbb{E}[R_{t+1} + \gamma \max_{a'} Q^*(S_{t+1}, a')]
```

这条式子已经告诉了我最优 `Q` 应该满足什么关系：

- 当前动作价值
- 等于当前 reward
- 加上下一个状态中最好的未来价值

但这里还有最后一个难点：

- 公式里有 `E`，说明本来应该对所有可能未来求期望
- 现实里我往往没有完整模型，不能直接把这个期望精确算出来

那怎么办？

最自然的办法就是：

> **用一次真实交互得到的 sample，去近似这个期望。**

也就是把：

```text
理论上的期望
```

变成：

```text
我这一次实际看到的 reward 和 next state
```

这样就从 Bellman optimality 自然长出了 Q-Learning 的 update：

```math
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'} Q(s',a') - Q(s,a)]
```

所以 Q-Learning 不是凭空发明出来的，它本质上是：

> **用 sample update 去逼近 Bellman optimality。**

---

#### 4. 如何验证这个思路是对的？

验证时不要死背公式，直接问三件事：

- **它有没有保留 Bellman 的结构？**
  - 有，仍然是 `当前 reward + 未来价值`
- **它有没有保留 Optimality 的目标？**
  - 有，未来价值那一项仍然是 `max_{a'} Q(s',a')`
- **它有没有把不可直接计算的期望，替换成可执行的学习步骤？**
  - 有，用一次 sample 的 `(r, s')` 来近似环境期望

如果这三点都成立，那它就是从 Bellman optimality 合法长出来的算法，而不是另起炉灶。

---

#### 5. 一个极小示例

假设当前在状态 `B`，做动作 `→` 后，观测到：

- 当前 reward `r = 0`
- 下一状态是 `C`
- 在 `C` 中目前最大的 Q 值是 `0.90`
- 折扣因子 `gamma = 0.9`
- 学习率 `alpha = 0.1`
- 当前 `Q(B, →) = 0.40`

那么 Bellman target 是：

```math
target = 0 + 0.9 \times 0.90 = 0.81
```

更新后：

```math
Q(B, →) \leftarrow 0.40 + 0.1 \times (0.81 - 0.40) = 0.441
```

这一步的含义很朴素：

- 原来我以为 `Q(B, →) = 0.40`
- 现在根据新经验发现，它看起来应该更接近 `0.81`
- 所以我把旧估计往新证据推近一点

这就是 Q-Learning 最本质的动作。

---

#### 6. 一句话收束

所以第四章真正要学的不是一个孤零零的 update 公式，而是一条完整推导链：

```text
未来影响当前决策
-> 长期价值必须递归分解
-> Bellman 给出正确结构
-> Optimality 指向最优动作价值
-> 期望太难直接算
-> 用 sample 逼近期望
-> 得到 Q-Learning
```

一句话：

> **Q-Learning 就是 Bellman Optimality Equation 的可执行版本。**

### 1. Q-Learning 想解决什么问题？

这一节不要先背公式，先抓住问题本身：

> **如果我想让 Agent 真正会选动作，只知道一个状态整体好不好，够不够？**

不够。

因为决策不是在问：

- 这个状态整体值多少钱

而是在问：

- 在这个状态下，往左还是往右？
- 现在加速值不值？
- 这个动作会把我带向更好的未来，还是更差的未来？

如果我只有：

```math
V(s)
```

那我得到的只是：

- 状态 `s` 整体上好不好

但真正决策时还差最后一刀：

- **哪个动作更好？**

所以这会自然逼出一个更细的对象：

```math
Q(s,a)
```

它表示：

> **在状态 `s` 下，如果我先做动作 `a`，未来总回报大概是多少？**

所以这一节真正要解决的是：

- `V(s)` 不足以直接选动作
- 要做控制，就必须学 `Q(s,a)`

一句话：

> **Q-Learning 不是在学“状态有多好”，而是在学“这个状态下哪个动作更值”。**

---

### 2. 如何表示这个解决方案？

既然目标已经变成：

> **我要知道每个状态下，每个动作到底值多少钱。**

那最自然的表示方式就是一张 `Q` 表：

```text
状态 s  ×  动作 a  ->  一个 Q 值
```

在一个很小的离散环境里，它可能长这样：

```text
          ←       →
A       0.12    0.45
B       0.30    0.81
C       0.10    0.90
```

这张表一旦学出来，策略其实就不需要额外发明了。

因为在每个状态里，直接选 Q 值最大的动作就行：

```math
\pi(s) = \arg\max_a Q(s,a)
```

比如上面这张表意味着：

- 在状态 `A`，选 `→`，因为 `0.45 > 0.12`
- 在状态 `B`，选 `→`，因为 `0.81 > 0.30`
- 在状态 `C`，选 `→`，因为 `0.90 > 0.10`

所以这里最关键的理解不是“Q 表长什么样”，而是：

- **Q 表不是规则表**
- **Q 表是动作价值表**
- **策略会从 Q 表里自然长出来**

这就是 Q-Learning 的核心设计：

> **不直接手写“该怎么做”，而是先学出“每个动作值多少”，再让动作选择自己从价值中长出来。**

---

### 3. 如何从 Bellman 推导出 Q-Learning？

现在问题和表示方式都有了，最后一步是：

> **我怎么更新这张 Q 表？**

这里就必须回到第三章的 `Bellman Optimality Equation`：

```math
Q^*(s,a) = \mathbb{E}[R_{t+1} + \gamma \max_{a'} Q^*(S_{t+1}, a')]
```

这条方程告诉我们的不是算法步骤，而是：

- **正确的最优动作价值，应该满足什么结构**

用人话翻译就是：

> 当前这个动作值多少，取决于两部分：
> 1. 这一步立刻拿到多少 reward
> 2. 下一状态中，最好的未来动作值多少

也就是：

```text
当前动作价值 = 当前收益 + 最优未来收益
```

但这里会立刻遇到一个现实问题：

- 方程里有 `E`
- 说明理论上应该对所有可能未来做期望
- 可现实里我们通常并不知道完整环境模型
- 所以没法直接精确算出右边

那怎么办？

最自然的解决办法就是：

> **拿一次真实经验 sample，去近似这个期望。**

也就是：

- 先执行一次动作，得到真实的 `r` 和 `s'`
- 再用当前 Q 表去估计 `s'` 里最好的未来价值
- 把它们拼成一个 Bellman target
- 然后把旧的 `Q(s,a)` 往这个 target 推近一点

于是自然得到：

```math
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'} Q(s',a') - Q(s,a)]
```

这一步推导非常关键，因为它说明：

- `r + \gamma \max_{a'} Q(s',a')` 不是拍脑袋写的
- 它就是 Bellman optimality 的 sample 版本
- `Q(s,a)` 不是一次就变成真值，而是反复逼近
- `\alpha` 的作用就是控制每次靠近多少

如何验证这个推导是对的？

直接检查三件事：

- 它有没有保留 Bellman 结构？
  - 有，仍然是 `当前 reward + 最优未来价值`
- 它有没有保留 optimality 的目标？
  - 有，未来那项仍然是 `\max_{a'} Q(s',a')`
- 它有没有把理论期望变成可执行步骤？
  - 有，用一次 sample 的 `(r, s')` 去近似环境期望

一个极小示例：

- 当前在状态 `B`
- 执行动作 `→`
- 得到 `r = 0`
- 到达 `C`
- 当前 `\max_{a'} Q(C,a') = 0.90`
- `\gamma = 0.9`
- `\alpha = 0.1`
- 旧值 `Q(B, →) = 0.40`

那么：

```math
target = 0 + 0.9 \times 0.90 = 0.81
```

更新后：

```math
Q(B, →) \leftarrow 0.40 + 0.1 \times (0.81 - 0.40) = 0.441
```

它表达的就是：

- 原来我以为这个动作值 `0.40`
- 新经验告诉我，它更像应该接近 `0.81`
- 所以我往新证据修正一点点

一句话收束：

> **Q-Learning = 用 sample update 去逼近 Bellman Optimality Equation。**

---

### 4. 这个更新公式到底在说什么？

我们把它拆开来看：

```math
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'}Q(s',a') - Q(s,a)]
```

#### 第 1 部分：`Q(s,a)`

这是旧估计。

意思是：
- 我之前认为，在状态 `s` 做动作 `a` 值这么多

---

#### 第 2 部分：`r + gamma * max Q(s', a')`

这是新的 Bellman target。

意思是：
- 当前这一步先拿到 reward `r`
- 然后看下一状态 `s'` 里，最好的未来动作价值是多少
- 两者合起来，就是这次更合理的目标

一句话：

> **target = 眼前收益 + 最好的未来收益**

---

#### 第 3 部分：`target - Q(s,a)`

这就是 TD error。

意思是：
- 新证据和旧估计差多少

如果：
- 结果是正的 -> 原来估低了
- 结果是负的 -> 原来估高了

---

#### 第 4 部分：`alpha * (...)`

这是学习率。

意思是：
- 这次要改多快
- `alpha` 大 -> 改得更猛
- `alpha` 小 -> 改得更稳

---

#### 第 5 部分：整体含义

整个更新公式其实只是在说一句非常朴素的话：

> **我原来对这个动作的判断，不一定准。**
> **这次看到新结果后，我把它往更合理的方向修一点。**

---

### 5. 一个最小例子：Q 值是怎么更新的？

假设：

- 当前状态是 `B`
- 你选择动作 `→`
- 得到奖励 `r = 0`
- 到达下一状态 `C`
- 当前 Q 表里，下一状态 `C` 的两个动作值分别是：

```text
Q(C, ←) = 0.20
Q(C, →) = 0.90
```

所以：

```math
\max_{a'} Q(C, a') = 0.90
```

再假设：

- `gamma = 0.9`
- `alpha = 0.1`
- 旧值 `Q(B, →) = 0.40`

那么 target 是：

```math
target = 0 + 0.9 	imes 0.90 = 0.81
```

TD error 是：

```math
0.81 - 0.40 = 0.41
```

更新后：

```math
Q(B, →) \leftarrow 0.40 + 0.1 	imes 0.41 = 0.441
```

也就是说：

- 原来你觉得 `B -> →` 值 `0.40`
- 这次经验告诉你，它应该更值钱一些
- 所以你把它从 `0.40` 往 `0.81` 推近一点，变成 `0.441`

一次更新只挪一点，但很多次之后，整张 Q 表就会越来越靠谱。

### 6. Q-Learning 为什么能"边学边变聪明"？

因为它会不断重复下面这个循环：

```text
1. 观察当前状态 s
2. 选择一个动作 a
3. 执行动作，得到 reward 和下一个状态 s'
4. 用 update 修正 Q(s,a)
5. 进入下一个状态继续
```

这个过程会带来两个效果：

#### 效果 1：奖励逐步向前传播

如果终点才有高 reward，那么：
- 先是终点前一格变得值钱
- 再是终点前两格变得值钱
- 再往前传

最终整张地图都会形成价值梯度。

#### 效果 2：策略会从 Q 表中自然长出来

刚开始 Q 表乱七八糟，动作也乱选。

但随着 Q 值越来越准确：
- 好动作的 Q 值会上升
- 差动作的 Q 值会下降

最后 Agent 只要选：

```math
\arg\max_a Q(s,a)
```

就能表现得越来越聪明。

---

### 7. 但这里还有一个新问题：如果永远只选当前最优，会不会学歪？

会。

这就是 RL 里另一个经典问题：

> **Exploration（探索）和 Exploitation（利用）怎么平衡？**

如果 agent 一开始就永远选"当前看起来最好的动作"，那它可能会卡在一个局部最优里。

比如：
- 它偶然发现"往左还行"
- 于是以后每次都往左
- 结果它永远不知道"往右可能更好"

所以 RL 不能只利用，还必须探索。

---

### 8. Epsilon-Greedy：Q-Learning 最常见的选动作方法

一种非常经典的做法叫：

```text
epsilon-greedy
```

规则是：

- 以概率 `epsilon` 随机选动作（探索）
- 以概率 `1 - epsilon` 选当前 Q 值最大的动作（利用）

比如：

- `epsilon = 1.0` -> 一开始几乎全随机
- `epsilon = 0.1` -> 90% 选当前最优，10% 随机探索
- `epsilon = 0.01` -> 基本稳定利用，只偶尔试新动作

一句话：

> **Epsilon-Greedy = 大多数时候用当前最优，少数时候故意乱试。**

通常训练时会让 `epsilon` 逐渐下降：

- 前期多探索
- 后期多利用

这就叫 `epsilon decay`。

---

### 9. Q-Learning 的完整训练流程

可以把它理解成下面这张流程图：

```text
初始化 Q 表
    ↓
环境 reset，得到初始状态 s
    ↓
根据 epsilon-greedy 选择动作 a
    ↓
执行动作，得到 r, s'
    ↓
用 Q-learning 公式更新 Q(s,a)
    ↓
状态变成 s'
    ↓
如果没结束，继续循环
    ↓
如果 episode 结束，开始下一局
```

这就是最经典的 tabular Q-Learning 流程。

env = gym.make("CartPole-v1")

#### 10.2 连续状态不能直接当表索引，所以先离散化

`CartPole` 的 observation 是连续值，比如：

于是连续状态就被映射成类似：

```python
(4, 6, 5, 3)
```

这样才能在 Q 表中定位：

```python
q_table[state]
```

---

#### 10.3 初始化 Q 表

```python
q_table = np.zeros((NUM_BINS, NUM_BINS, NUM_BINS, NUM_BINS, action_size))
```

意思是：
- 一开始我对所有状态动作都没有经验
- 所以先全部设成 `0`

---

#### 10.4 用 epsilon-greedy 选动作

```python
def choose_action(state, epsilon):
```

它做的事就是：
- 有时随机探索
- 有时选 `argmax(Q)`

这对应我们刚讲的 exploration / exploitation。

---

#### 10.5 用 Q-learning 公式更新 Q 表

代码核心通常长这样：

```python
old_q = q_table[state][action]
next_max = np.max(q_table[next_state])
target = reward + GAMMA * next_max
q_table[state][action] = old_q + ALPHA * (target - old_q)
```

这和公式是一一对应的：

```math
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'}Q(s',a') - Q(s,a)]
```

---

#### 10.6 epsilon 逐渐下降

```python
epsilon = max(EPSILON_END, epsilon * EPSILON_DECAY)
```

意思是：
- 开始时多探索
- 后面慢慢更相信自己已经学到的东西

这是 Q-learning 训练常见的节奏。

### 11. Q-Learning 的优点和局限

#### 优点

- 思想清晰
- 代码简单
- 很适合入门 RL
- 能把 Bellman、TD、探索利用这些核心概念串起来

#### 局限

- 需要 Q-table，状态空间太大时会爆炸
- 连续状态要先离散化，信息会损失
- 像 `CartPole` 这种还勉强能离散化
- 更复杂任务就不行了

这也是为什么后面会发展出：

- `DQN`：用神经网络代替 Q 表
- 更复杂的策略梯度、Actor-Critic 方法

所以可以把 Q-learning 看成：

> **理解 RL 核心思想的最经典第一站。**

---

### 12. 这一章的主线回顾

这一章真正想讲清楚的是：

1. **只知道状态值还不够，还需要动作值 `Q(s,a)`**
2. **Q-Learning 用 Bellman optimality 来定义"更合理的目标"**
3. **再用 update 公式把旧 Q 值往目标推进一点**
4. **通过不断交互，Q 表会越来越准确**
5. **策略不需要单独手写，可以直接从 Q 表里长出来**
6. **为了避免学歪，需要在 exploration 和 exploitation 之间平衡**

一句话收住：

> **Q-Learning 就是在不断试错中，把"哪个状态下该做哪个动作更划算"这件事学成一张表。**

---

### 本章速记卡片

#### 一句话主线

- `V` 只告诉你状态整体好不好
- `Q` 直接告诉你某个动作好不好
- `Q-Learning` 用 Bellman optimality 更新 Q 值
- 训练久了，策略就能从 Q 表里直接长出来

---

#### 必背公式

```math
Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'}Q(s',a') - Q(s,a)]
```

速记翻译：

- `Q(s,a)`：旧估计
- `r + gamma * max Q(s',a')`：Bellman target
- 中括号：TD error
- `alpha`：学习率

---

#### 必背术语

- `Q(s,a)`：状态 `s` 下动作 `a` 的长期价值
- `Q-table`：记录所有 `Q(s,a)` 的表
- `Exploration`：探索新动作
- `Exploitation`：利用当前最优动作
- `Epsilon-Greedy`：大多数时候选当前最优，少数时候随机探索

---

#### 最短背诵版

1. `Q` 比 `V` 更适合直接选动作
2. `Q-Learning` 学的是一张 `Q-table`
3. 更新目标是：`当前奖励 + 下一状态最好的未来价值`
4. 每次更新都把旧 Q 值往目标推一点
5. 用 `epsilon-greedy` 平衡探索和利用
6. 状态太大时，Q-table 不够用，于是后面会走向 `DQN`
